# Python 逐行执行观察器

在网页上逐行观察本机可信 Python 代码的实际执行：Flask + 原生 HTML/CSS/JavaScript，
每次运行在独立子进程中进行（`bdb` 跟踪），先停在首条待执行行，可单步、继续或终止。

## 启动

```bash
docker compose up --build
```

访问地址：<http://localhost:8000>（端口 **8000**）

本地直接运行（可选）：`pip install -r requirements.txt && python app.py`，同样访问 8000 端口。

## 功能

- 编辑器最多接受 **80 行**代码，超出会被拒绝；页面内置赋值、函数调用、循环、异常四个示例。
- **运行**：在独立子进程中启动，自动停在第一条待执行行；运行期间源码只读。
- **单步**：停在下一条实际将执行的源码行（会进入函数调用、跟随循环逐次迭代）。
- **继续**：一直执行到结束或异常；**终止**：强制结束并回收子进程。
- 实时显示：下一条待执行行（高亮 + `→`）、当前局部变量的文本值、标准输出、异常堆栈。
- 暂停中或死循环（继续后）都可以随时查询状态或终止。

## 并发与一致性规则

- 全站同一时刻只允许一个未结束的运行；结束后可修改代码再次运行。
- 控制请求（单步/继续/终止）携带 `run_id`；单步/继续还携带停顿序号 `pause_seq`。
- 同一次停顿最多接受一次控制请求：重复或过期请求返回 409 且不会推进执行。
- 前端只采纳与当前 `run_id` 匹配的状态响应，旧运行的迟到响应会被丢弃。

### 启动 / 终止 / 事件的协调（竞态修复）

启动一个运行分两步：先在服务端登记运行（分配 `run_id`、状态置为 running），再
`Popen` 创建 tracer 子进程。旧实现里这两步之间存在窗口：终止请求到来时虽然立刻把
状态改成 terminated 并返回成功，但 `proc` 还不存在、无法杀进程；随后原启动照常创建
子进程并开始喂代码。于是紧接着重跑可能留下两个存活子进程，旧 `run_id` 也再也终止
不了旧进程；此外，子进程被杀时管道里已缓冲的 pause/end 事件还会把 terminated 状态
改回 paused/running。

现在由一把条件变量统一协调启动、终止和事件读取，保证：

- **终止成功即无残留**：`/api/terminate` 返回 200 时，该运行的子进程已经死亡并被
  `wait()` 回收（无存活进程、无僵尸进程）。
- **启动期终止不丢**：终止在 `Popen` 尚未返回时到达会被登记；启动线程拿到进程句柄
  后自行杀掉并回收刚创建的子进程，未完成的启动不会再遗留进程。
- **旧进程回收前不接纳新运行**：`/api/run` 若发现上一个运行已终态但子进程尚未回收，
  会先等待回收完成再创建新子进程（等待超时返回 409“稍后重试”），两个子进程不可能
  并存。
- **终态粘滞、迟到事件丢弃**：事件只在该运行仍是“当前且活动”的运行时才被采用；
  terminated/finished/exception 之后到达的 pause、stdout、end 事件一律丢弃，状态
  不会从终态退回活动态；旧运行的事件也不会写入新运行。
- 子进程回收只在读取线程中进行一次（启动期终止时由启动线程回收），终止线程等待
  “已回收”信号而不是自己抢先 `wait()`，避免双重回收。
- 单运行冲突、过期控制请求仍返回 **409**；步进/继续的 `run_id`、`pause_seq` 与
  每次停顿至多一次的去重规则保持不变；`POST /api/run` 仍返回 `{run_id}`，
  `POST /api/terminate` 仍返回 `{ok, status}`，`GET /api/state` 结构不变。

### 重跑接纳：多个等待者抢槽（竞态修复）

复现：旧运行已结束（终态）但子进程尚未回收时，两个 `POST /api/run` 请求同时进入
等待。旧进程被回收后，先醒来的请求获准并登记新运行；若该运行很快报告终态（自然
结束、异常或被终止）而退出清理（读取线程的 `wait()` 回收）还没完成，另一个等待者
此时醒来，旧实现只检查“当前运行是否活动”，看到终态就放行——于是再登记一个运行
并创建子进程：两个存活子进程并存，且前一个运行的 `run_id` 立即失效（`CURRENT`
被顶替，旧标识无法再控制任何进程）。

修复后：`/api/run` 的接纳改为循环判断，每次从等待中醒来都重新读取**当时的**当前
运行：

- 当前运行是活动态 → 立即 409（活动运行占槽）；
- 当前运行是终态但子进程未回收 → 继续等它回收（与之前的等待共享同一截止时限，
  超时仍返回 409）；
- 当前运行是终态且已回收（或还没有任何运行）→ 才登记新运行并创建子进程。

等待期间绝不替换 `CURRENT`；子进程退出并被回收之前，绝不登记或创建下一运行，
因此任意时刻至多一个存活 tracer 子进程，等待中超时也不会提前顶替当前运行。

核对用测试（含可控线程交错：门控 `Popen` 复现“已登记未挂接”窗口、启动后立即重跑、
终止后灌入迟到事件、两个重跑请求同时等待回收且替代运行终态未回收、等待者醒来遇到
活动运行占槽、回收超时 409，以及正常暂停/步进/继续和死循环终止）：

```bash
pip install -r requirements.txt
python3 -m unittest test_races -v
```

其中 `test_stress_run_terminate_rerun` 用多线程在不加门控的真实交错下反复
运行→立即终止→立即重跑，并采样确认任意时刻至多一个存活 tracer 子进程、全部进程
最终被回收。`test_waiters_cannot_overtake_unreaped_replacement` 用门控的
`_wait_reaped` 精确复现上述抢槽窗口：两个等待中的重跑请求在“替代运行终态未回收”
时必须继续等待、不得创建第二个子进程，替代运行回收后恰好一个请求被接纳、另一个
收到 409。

## 限制

- 不支持交互式输入（`input()` 会得到 EOF 异常）与第三方包（仅标准库）。
- 标准输出保留最近约 100K 字符，超出部分截断。

## 接口

| 方法 | 路径 | 请求体 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/run` | `{code}` | 启动运行，返回 `{run_id}`；已有活动运行返回 409 |
| POST | `/api/step` | `{run_id, pause_seq}` | 单步；重复/过期返回 409 |
| POST | `/api/continue` | `{run_id, pause_seq}` | 继续至结束；重复/过期返回 409 |
| POST | `/api/terminate` | `{run_id}` | 终止并回收子进程；成功返回时子进程已死亡且被回收；运行不存在/已过期/已结束返回 409 |
| GET | `/api/state` | — | 当前运行完整状态（含 `run_id`、行号、局部变量、输出、异常） |
